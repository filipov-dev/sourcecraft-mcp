# Решение проблем

## Homebrew не ставит формулу из стороннего tap

Новые версии Homebrew не устанавливают формулы из сторонних tap по короткому имени. Устанавливайте по полному имени:

```bash
brew install filipov-dev/tap/sourcecraft-mcp
```

Если `brew tap filipov-dev/tap` без адреса не находит tap — он размещён на SourceCraft, а не на GitHub, поэтому нужен полный адрес:

```bash
brew tap filipov-dev/tap https://git.sourcecraft.dev/filipov-dev/homebrew-tap.git
```

## macOS: Keychain спрашивает разрешение

macOS может спросить, разрешить ли `sourcecraft-mcp` доступ к записи `dev.filipov.sourcecraft-mcp` в связке ключей, — обычно когда токен сохранила одна сборка бинарника, а читает другая. Нажмите «Всегда разрешать», иначе вопрос будет повторяться при каждом запуске сервера.

Бинарник из Homebrew и релизных архивов подписан Developer ID, поэтому после обновления разрешение, как правило, сохраняется. Бинарник, собранный из исходников, подписью разработчика не подписан: после каждой пересборки macOS считает его новой программой и спрашивает снова.

Когда сервер запускает MCP-клиент, окно с вопросом появляется поверх других окон, а клиент ждёт ответа. Если клиент пишет, что сервер не запустился или не ответил, проверьте, нет ли такого окна.

## Linux: Secret Service недоступен

В Linux токен хранится через Secret Service (D-Bus). Библиотека `libdbus-1` не нужна: бинарник обращается к шине сам. Ошибка системного хранилища токенов при `connect`, `auth login` или `serve` обычно означает одно из:

- в сессии не запущен провайдер Secret Service — GNOME Keyring, KeePassXC (с включённой интеграцией Secret Service), KWallet и т. п.;
- нет сессионной шины D-Bus: например, при входе по SSH на сервер без графической сессии;
- связка ключей заблокирована и разблокировать её некому.

На машине без графической сессии запустите провайдер Secret Service в сессии D-Bus пользователя или используйте `sourcecraft-mcp` на рабочей машине с графической сессией. Хранить токен в переменной окружения или файле нельзя — это намеренное ограничение.

## Linux: «No CA certificates were loaded from the system»

`serve`, `connect` и `auth login` проверяют сертификат SourceCraft по корневым сертификатам системы. В минимальных образах (Debian/Ubuntu slim и т. п.) их нет: поставьте пакет `ca-certificates` (`apt-get install ca-certificates`) или укажите файл сертификатов в переменной `SSL_CERT_FILE`.

## «no SourceCraft token is stored for profile …»

Для профиля, указанного в `serve --profile` (или `secret --profile`), нет токена в системном хранилище. Проверьте имя профиля в конфигурации клиента и сохраните токен:

```bash
sourcecraft-mcp auth status --profile <профиль>
sourcecraft-mcp auth login --profile <профиль>
```

Помните, что профиль по умолчанию для `serve` и `auth` — `default`, а `connect` по умолчанию создаёт профиль с именем клиента (`claude-code`, `codex`).

## «SourceCraft rejected the token (HTTP 401/403)»

Токен скопирован не полностью, истёк или отозван. Создайте новый токен (Home → Access → Personal access tokens) и замените сохранённый:

```bash
sourcecraft-mcp auth login --profile <профиль>
```

Если проверка не проходит по другой причине (нет сети, прокси), можно сохранить токен без проверки: `--skip-check`.

## Клиент не видит сервер или его инструменты

- Перезапустите клиент после `connect` или правки конфигурации.
- Укажите в конфигурации клиента абсолютный путь к бинарнику (`command -v sourcecraft-mcp`): клиенты, запущенные не из терминала, часто не видят `PATH` оболочки.
- Запустите команду из конфигурации клиента вручную, например `sourcecraft-mcp serve --profile codex`. Ошибки запуска (нет токена, неизвестный набор, флаг доступа сверх прав профиля, каталог `--allow-path` вне каталогов профиля) печатаются в stderr, как и предупреждение о неодобренных правах на macOS. Если ошибок нет, сервер ждёт сообщений MCP на stdin — остановите его `Ctrl-C`.
- Для подробных логов задайте `SOURCECRAFT_MCP_LOG=debug` в окружении сервера (в конфигурации клиента, если он это поддерживает). Логи пишутся в stderr.

## Агенту не хватает инструмента

По умолчанию сервер работает только на чтение, а `--toolsets` может скрыть целые разделы API. Агент может найти любую операцию через `api_search`: результат покажет, зарегистрирован ли инструмент и какой уровень доступа или набор его включает. Уровень поднимается в правах профиля: `sourcecraft-mcp ui` (вкладка Access) или `connect … --allow-write`, затем перезапустите клиент. Наборы меняются флагом `--toolsets` в `connect` или в `args` конфигурации клиента.

На macOS проверьте и одобрение: `sourcecraft-mcp auth status --profile <имя>` показывает строку `Approval`, а сервер, у которого права в профиле шире одобренных, работает с одобренными (без одобрения — только на чтение) и пишет предупреждение в stderr. Одобрить права можно, сохранив их в `sourcecraft-mcp ui` с Touch ID или паролем.

## Файл «is outside the allowed directories»

Инструменты работают с локальными файлами только в рабочем каталоге сервера, системном временном каталоге и каталогах `allow_path` профиля. Если клиент запускает сервер в домашнем каталоге или в `/`, рабочий каталог не разрешён. Добавьте нужный каталог в права профиля: `sourcecraft-mcp ui`, вкладка Access, клавиша `a`. Подробнее — [Безопасность](security.md#локальные-файлы).

## Ответ обрезан

Ответы больше `--max-response-bytes` (256 KiB по умолчанию) обрезаются. Запросите меньше данных (`page_size`, фильтры), оставьте только нужные поля [фильтром `jq`](tools.md#фильтр-ответа-jq) или увеличьте лимит в аргументах сервера.
