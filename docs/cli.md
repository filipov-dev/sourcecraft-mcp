# Справочник CLI

```text
sourcecraft-mcp <команда> [флаги]
```

| Команда | Назначение |
| --- | --- |
| [`serve`](#serve) | Запустить MCP-сервер через stdio. Её запускает MCP-клиент. |
| [`connect`](#connect) | Сохранить токен и зарегистрировать сервер в Claude Code или Codex. |
| [`auth`](#auth) | Управлять токенами профилей: `status`, `login`, `logout`. |
| [`secret`](#secret) | Использовать секреты репозитория в командах, не показывая значения: `exec`, `write`, `list`, `get`. |
| [`toolsets`](#toolsets) | Показать наборы инструментов для `--toolsets`. |

`sourcecraft-mcp --version` печатает версию, `sourcecraft-mcp <команда> --help` — справку по команде.

## Профили

Профиль — имя, под которым хранятся токен и настройки одного клиента.

- **Токен** — в системном хранилище: macOS Keychain, Secret Service в Linux, Credential Manager в Windows. Сервис `dev.filipov.sourcecraft-mcp`, учётная запись — имя профиля.
- **Настройки** (без токена) — в `~/.config/sourcecraft-mcp/profiles.toml`; в Linux учитывается `XDG_CONFIG_HOME`. Файл создают `connect` и `auth login`:

  ```toml
  [profiles.codex]
  client = "codex"
  allow_write = true
  allow_destructive = false
  toolsets = ["repository", "issues"]
  allow_secret_values = false
  ```

Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

## serve

```text
sourcecraft-mcp serve [флаги]
```

Запускает MCP-сервер через stdio. stdout занят протоколом MCP, логи и ошибки запуска пишутся в stderr. Обычно команду запускает MCP-клиент, а не человек.

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `default` | Профиль, из которого берутся токен и настройки. |
| `--allow-write` | выкл. | Регистрировать инструменты, которые создают и меняют данные. |
| `--allow-destructive` | выкл. | Регистрировать инструменты удаления и другие необратимые операции; включает `--allow-write`. |
| `--toolsets <a,b,…>` | все наборы | Только указанные наборы инструментов (см. [`toolsets`](#toolsets)). Неизвестный набор — ошибка запуска. |
| `--allow-secret-values` | выкл. | Разрешить показывать значения секретов, если вызов явно просит (`reveal_values: true`). |
| `--allow-path <каталог>` | — | Дополнительный каталог для чтения и сохранения локальных файлов. Можно повторять; каталог должен существовать. |
| `--base-url <URL>` | `$SOURCECRAFT_BASE_URL` или `https://api.sourcecraft.tech` | Адрес SourceCraft API. |
| `--timeout <секунды>` | `60` | Таймаут одного запроса к API. |
| `--max-response-bytes <байты>` | `262144` (256 KiB) | Наибольший размер ответа API, который получает агент; больший ответ обрезается с пояснением. |

Флаги командной строки и настройки профиля:

- **Уровень доступа.** Если задан `--allow-write` или `--allow-destructive`, используется он; иначе — настройки профиля; без них — только чтение.
- **Наборы.** Если задан `--toolsets`, используется он; иначе — наборы из профиля; без них — все.
- **Значения секретов** разрешены, если задан `--allow-secret-values` или это включено в профиле.

Если для профиля нет токена, `serve` завершается с ошибкой и подсказкой, как его сохранить. Переменные окружения и `.env` для токена не используются.

## connect

```text
sourcecraft-mcp connect <claude-code|codex> [флаги]
```

Создаёт или обновляет профиль и регистрирует сервер `sourcecraft` в клиенте. Подробное описание шагов — [Подключение к MCP-клиентам](clients.md#claude-code-и-codex-connect).

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | имя клиента | Профиль токена. |
| `--scope <user\|project>` | `user` | `user` — для всех проектов пользователя; `project` — в `.mcp.json` текущего каталога (только Claude Code). |
| `--allow-write` | выкл. | Разрешить инструменты записи. |
| `--allow-destructive` | выкл. | Разрешить инструменты удаления. |
| `--toolsets <a,b,…>` | все | Наборы инструментов. |
| `--allow-secret-values` | выкл. | Разрешить агенту запрашивать значения секретов. |
| `-y`, `--yes` | выкл. | Не спрашивать подтверждение перед изменением конфигурации клиента. |
| `--skip-check` | выкл. | Сохранить токен без проверки запросом к API. |

Флаги сохраняются в профиль и записываются в команду запуска в конфигурации клиента. Повторный `connect` перезаписывает профиль и запись в клиенте целиком; если токен уже сохранён, он используется, а заменить его можно командой `auth login`.

Токен проверяется по адресу из `SOURCECRAFT_BASE_URL` или адресу по умолчанию.

## auth

### auth status

```text
sourcecraft-mcp auth status [--profile <имя>]
```

Показывает, сохранён ли токен профиля (без значения), клиент, разрешены ли запись и удаление, выбранные наборы и путь к `profiles.toml`. Профиль по умолчанию — `default`.

### auth login

```text
sourcecraft-mcp auth login [--profile <имя>] [--skip-check]
```

Принимает токен скрытым вводом, проверяет его запросом `GET /user` (если не задан `--skip-check`) и сохраняет в системное хранилище, заменяя прежний. Если профиля ещё нет в `profiles.toml`, создаёт его с настройками по умолчанию (только чтение). MCP-клиенты не трогает — используйте для ручного подключения или чтобы заменить токен.

### auth logout

```text
sourcecraft-mcp auth logout [--profile <имя>] [--forget]
```

Удаляет токен профиля из системного хранилища. С `--forget` также удаляет настройки профиля из `profiles.toml`. Запись в конфигурации MCP-клиента остаётся — удалите её сами. Токен в SourceCraft после этого стоит отозвать: Home → Access → Personal access tokens.

## secret

Команды для работы с секретами репозитория (секретами CI) из оболочки. Агент может с их помощью использовать секрет, не получая его значения. Подробности и ограничения маскирования — [Безопасность](security.md#секреты-в-командах-оболочки).

Общие флаги всех команд `secret`:

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `$SOURCECRAFT_MCP_PROFILE`, иначе `default` | Профиль токена. Переменная задаёт только имя профиля, не токен. |
| `--repo <org>/<repo>` | — | Репозиторий по slug. |
| `--repo-id <ID>` | — | Репозиторий по ID, вместо `--repo`. |
| `--group <имя>` | группа API по умолчанию | Группа секретов. |
| `--base-url <URL>` | `$SOURCECRAFT_BASE_URL` или `https://api.sourcecraft.tech` | Адрес SourceCraft API. |

### secret exec

```text
sourcecraft-mcp secret exec --repo <org>/<repo> (--env NAME=KEY … | --all) [--prefix P] -- <команда> [аргументы…]
```

Запускает команду с секретами в переменных окружения.

| Флаг | Назначение |
| --- | --- |
| `-e`, `--env NAME=KEY` | Переменная `NAME` получает значение секрета `KEY`. Форма `--env KEY` — переменная `<prefix>KEY`. Можно повторять. |
| `--all` | Все секреты репозитория, каждый под своим ключом (с `--prefix`). Явные `--env` важнее `--all` при совпадении имени. |
| `--prefix <P>` | Префикс имён переменных, полученных из ключей (`--all` и `--env KEY`). |

- Команда запускается напрямую, без оболочки; stdin наследуется; возвращается код завершения команды.
- В stdout и stderr команды значения переданных секретов и их base64 заменяются на `***`. Значения короче 4 байт не маскируются — об этом, как и о пустом значении, предупреждение в stderr с именем ключа (без значения).
- Ключ, которого нет в репозитории, — ошибка до запуска команды. Имя переменной: `[A-Za-z_][A-Za-z0-9_]*`.
- Чтобы использовать `$NAME` в командной строке, запустите оболочку сами и возьмите скрипт в одинарные кавычки: переменную раскроет дочерняя оболочка.

```bash
sourcecraft-mcp secret exec --repo acme/web --env CONF=APP_CONFIG -- \
  sh -c 'printf %s "$CONF" | ssh deploy@host "cat > /etc/app/config"'
```

### secret write

```text
sourcecraft-mcp secret write --repo <org>/<repo> <KEY> --to <путь> [--mode 600] [--force]
```

Записывает значение секрета в новый файл и печатает только путь и число байт. Пригодится программам, которым нужен файл (`ssh -i`, `scp -i`).

| Флаг | Назначение |
| --- | --- |
| `--to <путь>` | Файл, который нужно создать. |
| `--mode <восьмеричное>` | Права файла, по умолчанию `600`. |
| `--force` | Заменить существующий файл. Без флага существующий файл или символическая ссылка не перезаписываются. |

```bash
sourcecraft-mcp secret write --repo acme/web DEPLOY_KEY --to /tmp/deploy_key && \
  scp -i /tmp/deploy_key build.tar deploy@host: ; rm -f /tmp/deploy_key
```

Удаляйте файл, когда он больше не нужен.

### secret list

```text
sourcecraft-mcp secret list --repo <org>/<repo>
```

Печатает ключи секретов, без значений.

### secret get

```text
sourcecraft-mcp secret get --repo <org>/<repo> <KEY> --reveal
```

Печатает значение секрета в stdout как есть. Без `--reveal` завершается ошибкой и предлагает `exec` или `write`. Если stdout не терминал, в stderr печатается напоминание, что значение попало в вывод вызывающей программы. Используйте, только когда значение действительно нужно увидеть.

## toolsets

```text
sourcecraft-mcp toolsets
```

Печатает наборы инструментов: slug для `--toolsets`, число операций и тег спецификации SourceCraft. Подробнее — [MCP-инструменты](tools.md#наборы-инструментов).

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `SOURCECRAFT_BASE_URL` | Адрес SourceCraft API для `serve`, `connect`, `auth login` и `secret`, если не задан `--base-url`. |
| `SOURCECRAFT_MCP_PROFILE` | Профиль по умолчанию для команд `secret`. |
| `SOURCECRAFT_MCP_LOG` | Уровень логов в stderr в формате `tracing` `EnvFilter`: `warn` (по умолчанию), `info`, `debug`. |
| `SOURCECRAFT_MCP_CONFIG_DIR` | Каталог с `profiles.toml` вместо `~/.config/sourcecraft-mcp`. |
| `CODEX_HOME` | Каталог конфигурации Codex для `connect codex`, по умолчанию `~/.codex`. |

Токен SourceCraft из переменных окружения не читается никогда.
