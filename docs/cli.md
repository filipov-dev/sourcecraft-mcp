# Справочник CLI

```text
sourcecraft-mcp <команда> [флаги]
```

| Команда | Назначение |
| --- | --- |
| [`serve`](#serve) | Запустить MCP-сервер через stdio (её запускает MCP-клиент) или HTTP (`--http`). |
| [`connect`](#connect) | Сохранить токен и зарегистрировать сервер в Claude Code или Codex. |
| [`auth`](#auth) | Управлять токенами профилей: `status`, `login`, `logout`. |
| [`secret`](#secret) | Использовать секреты репозитория в командах, не показывая значения: `exec`, `write`, `list`, `get`, `copy`. |
| [`call`](#call) | Вызвать инструмент сервера из консоли с правами профиля. |
| [`ui`](#ui) | Интерактивный просмотр профилей, прав, регистраций в клиентах и токена. |
| [`toolsets`](#toolsets) | Показать наборы инструментов для `--toolsets`. |

`sourcecraft-mcp --version` печатает версию, `sourcecraft-mcp <команда> --help` — справку по команде.

## Профили

Профиль — имя, под которым хранятся токен и настройки одного клиента.

- **Токен** — в системном хранилище: macOS Keychain, Secret Service в Linux, Credential Manager в Windows. Сервис `dev.filipov.sourcecraft-mcp`, учётная запись — имя профиля.
- **Настройки** (без токена) — в `~/.config/sourcecraft-mcp/profiles.toml`; в Linux учитывается `XDG_CONFIG_HOME`, в Windows файл лежит в `%APPDATA%\sourcecraft-mcp\profiles.toml`. Файл создают `connect` и `auth login`:

  ```toml
  [profiles.codex]
  client = "codex"
  allow_write = true
  allow_destructive = false
  allow_path = ["/home/me/work"]   # записывается, только если задано
  toolsets = ["repository", "issues"]
  allow_secret_values = false
  dynamic_toolsets = true   # записывается, только если включено
  ```

- **Права профиля** (`allow_write`, `allow_destructive`, `allow_path`) — граница доступа stdio-сервера: `serve`, `call` и `ui` не дают больше. Меняет их `sourcecraft-mcp ui` (или `connect --allow-write`/`--allow-destructive`, или правка файла). На macOS права сверх чтения действуют только после одобрения владельцем: одобренная копия прав хранится в Keychain (сервис `sourcecraft-mcp.access`, учётная запись — имя профиля), а `ui` и `connect` при повышении прав спрашивают Touch ID или пароль пользователя macOS. Понижение прав одобрения не требует. Если права в профиле шире одобренных, действует пересечение; если одобрения нет или Keychain недоступен — только чтение, сервер предупреждает в stderr. В Linux и Windows одобрения нет: права ограничивают роли токена в SourceCraft ([Безопасность](security.md#уровни-доступа)).

Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

## serve

```text
sourcecraft-mcp serve [флаги]
```

Запускает MCP-сервер через stdio. stdout занят протоколом MCP, логи и ошибки запуска пишутся в stderr. Обычно команду запускает MCP-клиент, а не человек.

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `default` | Профиль, из которого берутся токен и настройки. |
| `--allow-write` | выкл. | Сузить права профиля до записи (профиль должен её разрешать). С `--http` — регистрировать инструменты, которые создают и меняют данные. |
| `--allow-destructive` | выкл. | Ограничить права уровнем удаления (профиль должен его разрешать). С `--http` — регистрировать инструменты удаления и другие необратимые операции; включает `--allow-write`. |
| `--toolsets <a,b,…>` | все наборы | Только указанные наборы инструментов (см. [`toolsets`](#toolsets)). Неизвестный набор — ошибка запуска. С `--dynamic-toolsets` — наборы, включённые при запуске. |
| `--dynamic-toolsets` | выкл. | Динамические наборы: при запуске только `api_search`, `api_request`, `list_toolsets`, `enable_toolset`, `disable_toolset` и пользовательские инструменты; агент включает наборы сам (см. [MCP-инструменты](tools.md#динамические-наборы)). Не сочетается с `--http`. |
| `--allow-secret-values` | выкл. | Разрешить показывать значения секретов, если вызов явно просит (`reveal_values: true`). |
| `--allow-keychain-source` | выкл. | Разрешить `secret_copy` читать записи системного хранилища этой машины (`keychain://<service>/<account>`) и загружать их в секреты репозиториев. Записи с токенами `sourcecraft-mcp` и одобренными правами (`sourcecraft-mcp.access`) недоступны всегда. Не сочетается с `--http`. |
| `--allow-path <каталог>` | каталоги профиля | Оставить из каталогов `allow_path` профиля только указанный (он должен лежать внутри одного из них). Можно повторять. |
| `--base-url <URL>` | `$SOURCECRAFT_BASE_URL` или `https://api.sourcecraft.tech` | Адрес SourceCraft API. |
| `--timeout <секунды>` | `60` | Таймаут одного запроса к API. |
| `--tools-file <путь>` | — | Дополнительный файл [пользовательских инструментов](tools.md#пользовательские-инструменты), кроме `~/.config/sourcecraft-mcp/tools.toml`. Можно повторять. Ошибка в файле — ошибка запуска. |
| `--max-response-bytes <байты>` | `262144` (256 KiB) | Наибольший размер ответа API, который получает агент; больший ответ обрезается с пояснением. С [фильтром `jq`](tools.md#фильтр-ответа-jq) лимит применяется к результату фильтра. |

Флаги командной строки и настройки профиля:

- **Уровень доступа и каталоги** — из профиля ([Профили](#профили)); без настроек — только чтение и без дополнительных каталогов. Флаги `--allow-write`, `--allow-destructive` и `--allow-path` права только сужают: флаг, который просит больше, чем разрешено в профиле, — ошибка запуска с подсказкой. На macOS права сверх одобренных отсекаются с предупреждением в stderr, сервер при этом запускается. Регистрации старых версий с флагами доступа в `args` продолжают запускаться, пока флаги не шире профиля; повторный `connect` переписывает их без флагов.
- **Наборы.** Если задан `--toolsets`, используется он; иначе — наборы из профиля; без них — все.
- **Значения секретов** разрешены, если задан `--allow-secret-values` или это включено в профиле.
- **Динамические наборы** включены, если задан `--dynamic-toolsets` или это включено в профиле.

Если для профиля нет токена, `serve` завершается с ошибкой и подсказкой, как его сохранить. Переменные окружения и `.env` для токена не используются.

### serve --http

```text
sourcecraft-mcp serve --http [--listen <IP:порт>] [--allowed-host <имя>]… [--allowed-origin <origin>]… [флаги]
```

Запускает MCP-сервер по HTTP: `POST /mcp` (Streamable HTTP без сессий) и `GET /health`. Профилей нет: каждый запрос несёт токен агента в `Authorization: Bearer <токен>`, без него — `401`. Уровень доступа, наборы и `--allow-secret-values` берутся только из флагов: профиля и одобрения на macOS в этом режиме нет (почему — [HTTP-режим](http.md#отличия-от-stdio)). `--profile` и `--allow-path` вместе с `--http` — ошибка; флаги ниже без `--http` — тоже.

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--http` | выкл. | Режим HTTP вместо stdio. |
| `--listen <IP:порт>` | `127.0.0.1:8765` | Адрес и порт. Не loopback — предупреждение: нужен TLS. |
| `--allowed-host <имя>` | — | Дополнительное допустимое значение `Host` (`имя` или `имя:порт`). Можно повторять. |
| `--allowed-origin <origin>` | — | Допустимый `Origin` браузерного клиента. Можно повторять. Запросы без `Origin` принимаются всегда. |

Запуск в Docker, Compose и systemd, подключение агентов и модель угроз — [HTTP-режим](http.md).

## connect

```text
sourcecraft-mcp connect <claude-code|codex> [флаги]
```

Создаёт или обновляет профиль и регистрирует сервер `sourcecraft` в клиенте. Подробное описание шагов — [Подключение к MCP-клиентам](clients.md#claude-code-и-codex-connect).

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | имя клиента | Профиль токена. |
| `--scope <user\|project>` | `user` | `user` — для всех проектов пользователя; `project` — в `.mcp.json` текущего каталога (только Claude Code). |
| `--allow-write` | права не меняются | Поставить профилю уровень записи. |
| `--allow-destructive` | права не меняются | Поставить профилю уровень удаления; включает запись (в профиль сохраняются оба значения). |
| `--toolsets <a,b,…>` | все | Наборы инструментов. |
| `--dynamic-toolsets` | выкл. | Наборы включаются агентом по запросу (`serve --dynamic-toolsets`). |
| `--allow-secret-values` | выкл. | Разрешить агенту запрашивать значения секретов. |
| `-y`, `--yes` | выкл. | Не спрашивать подтверждение перед изменением конфигурации клиента. |
| `--skip-check` | выкл. | Сохранить токен без проверки запросом к API. |
| `--no-browser` | выкл. | Не открывать форму создания токена в браузере, только напечатать ссылку. |

Клиент получает только команду `<абсолютный путь к sourcecraft-mcp> serve --profile <профиль> [--toolsets …] [--dynamic-toolsets] [--allow-secret-values]`. Ни токена, ни флагов доступа в конфигурации клиента нет: `serve` берёт токен из системного хранилища, а права — из профиля.

Без `--allow-write` и `--allow-destructive` права профиля не меняются (у нового профиля — только чтение). С флагом профиль получает этот уровень; на macOS повышение прав спрашивает Touch ID или пароль, и при отказе профиль сохраняет прежние права, а токен и регистрация всё равно сохраняются. Каталоги `allow_path` профиля `connect` не трогает. Остальные флаги (`--toolsets`, `--dynamic-toolsets`, `--allow-secret-values`) сохраняются в профиль и записываются в команду запуска. Повторный `connect` перезаписывает запись в клиенте, в том числе регистрацию старой версии с флагами доступа; если токен уже сохранён, он используется, а заменить его можно командой `auth login`.

Если токена для профиля ещё нет, `connect` открывает в браузере форму создания токена <https://sourcecraft.dev/me/create-token> и печатает, как её заполнить. Браузер не открывается с `--no-browser`, по SSH (`SSH_CONNECTION`, `SSH_TTY`) и в Linux без графической сессии (`DISPLAY`, `WAYLAND_DISPLAY`); ссылка печатается всегда.

Токен проверяется по адресу из `SOURCECRAFT_BASE_URL` или адресу по умолчанию.

## auth

### auth status

```text
sourcecraft-mcp auth status [--profile <имя>]
```

Показывает, сохранён ли токен профиля (без значения), клиент, права профиля (уровень и каталоги `allow_path`), состояние одобрения на macOS (строка `Approval`, а если права шире одобренных — `Warning`), выбранные наборы и путь к `profiles.toml`. Профиль по умолчанию — `default`.

### auth login

```text
sourcecraft-mcp auth login [--profile <имя>] [--skip-check] [--no-browser]
```

Открывает форму создания токена в браузере так же, как `connect` (`--no-browser` — только напечатать ссылку), принимает токен скрытым вводом, проверяет его запросом `GET /user` (если не задан `--skip-check`) и сохраняет в системное хранилище, заменяя прежний. Если профиля ещё нет в `profiles.toml`, создаёт его с настройками по умолчанию (только чтение). MCP-клиенты не трогает — используйте для ручного подключения или чтобы заменить токен.

### auth logout

```text
sourcecraft-mcp auth logout [--profile <имя>] [--forget]
```

Удаляет токен профиля из системного хранилища. С `--forget` также удаляет настройки профиля из `profiles.toml`. Запись в конфигурации MCP-клиента остаётся — удалите её сами. Токен в SourceCraft после этого стоит отозвать: Home → Access → Personal access tokens.

## secret

Команды для работы с секретами репозитория (секретами CI) из оболочки. Агент может с их помощью использовать секрет, не получая его значения. Подробности и ограничения маскирования — [Безопасность](security.md#секреты-в-командах-оболочки).

Общие флаги команд `exec`, `write`, `list` и `get` (у `copy` свои, см. [ниже](#secret-copy)):

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `$SOURCECRAFT_MCP_PROFILE`, иначе `default` | Профиль токена. Переменная задаёт только имя профиля, не токен. |
| `--repo <org>/<repo>` | — | Репозиторий по slug. |
| `--repo-id <ID>` | — | Репозиторий по ID, вместо `--repo`. |
| `--group <имя>` | группа API по умолчанию | Группа секретов. |
| `--base-url <URL>` | `$SOURCECRAFT_BASE_URL` или `https://api.sourcecraft.tech` | Адрес SourceCraft API. |

### secret exec

```text
sourcecraft-mcp secret exec --repo <org>/<repo> (--env NAME=KEY … | --all) [--prefix P] -- <команда> [аргументы…]
```

Запускает команду с секретами в переменных окружения.

| Флаг | Назначение |
| --- | --- |
| `-e`, `--env NAME=KEY` | Переменная `NAME` получает значение секрета `KEY`. Форма `--env KEY` — переменная `<prefix>KEY`. Можно повторять. |
| `--all` | Все секреты репозитория, каждый под своим ключом (с `--prefix`). Явные `--env` важнее `--all` при совпадении имени. |
| `--prefix <P>` | Префикс имён переменных, полученных из ключей (`--all` и `--env KEY`). |

- Команда запускается напрямую, без оболочки; stdin наследуется; возвращается код завершения команды.
- В stdout и stderr команды значения переданных секретов и их base64 заменяются на `***`. Значения короче 4 байт не маскируются — об этом, как и о пустом значении, предупреждение в stderr с именем ключа (без значения).
- Ключ, которого нет в репозитории, — ошибка до запуска команды. Имя переменной: `[A-Za-z_][A-Za-z0-9_]*`.
- Чтобы использовать `$NAME` в командной строке, запустите оболочку сами и возьмите скрипт в одинарные кавычки: переменную раскроет дочерняя оболочка.

```bash
sourcecraft-mcp secret exec --repo acme/web --env CONF=APP_CONFIG -- \
  sh -c 'printf %s "$CONF" | ssh deploy@host "cat > /etc/app/config"'
```

В Windows без `sh` (PowerShell, `cmd`) так же запускается `powershell`, переменная внутри кавычек — `$env:NAME`:

```powershell
sourcecraft-mcp secret exec --repo acme/web --env KEY=API_KEY -- powershell -NoProfile -Command '.\deploy.ps1 -ApiKey $env:KEY'
```

### secret write

```text
sourcecraft-mcp secret write --repo <org>/<repo> <KEY> --to <путь> [--mode 600] [--force]
```

Записывает значение секрета в новый файл и печатает только путь и число байт. Пригодится программам, которым нужен файл (`ssh -i`, `scp -i`).

| Флаг | Назначение |
| --- | --- |
| `--to <путь>` | Файл, который нужно создать. |
| `--mode <восьмеричное>` | Права файла, по умолчанию `600`. В Windows не применяются: файл наследует права каталога, поэтому пишите его в каталог внутри своего профиля (например, `%LOCALAPPDATA%\Temp`), а не в общий. |
| `--force` | Заменить существующий файл. Без флага существующий файл или символическая ссылка не перезаписываются. |

```bash
sourcecraft-mcp secret write --repo acme/web DEPLOY_KEY --to /tmp/deploy_key && \
  scp -i /tmp/deploy_key build.tar deploy@host: ; rm -f /tmp/deploy_key
```

Удаляйте файл, когда он больше не нужен.

### secret list

```text
sourcecraft-mcp secret list --repo <org>/<repo>
```

Печатает ключи секретов, без значений.

### secret get

```text
sourcecraft-mcp secret get --repo <org>/<repo> <KEY> --reveal
```

Печатает значение секрета в stdout как есть. Без `--reveal` завершается ошибкой и предлагает `exec` или `write`. Если stdout не терминал, в stderr печатается напоминание, что значение попало в вывод вызывающей программы. Используйте, только когда значение действительно нужно увидеть.

### secret copy

```text
sourcecraft-mcp secret copy [--profile P] [--base-url URL] [--force] <источник> <назначение>
```

Копирует секрет, не печатая значение. Ссылки:

- `sc://<org>/<repo>/<KEY>` — секрет репозитория; группа секретов — `?group=<имя>` в конце;
- `keychain://<service>/<account>` — запись системного хранилища этой машины (macOS Keychain, Secret Service, Credential Manager).

И источник, и назначение могут быть любого вида: из репозитория в репозиторий, из хранилища в репозиторий и обратно. Существующее назначение заменяется только с `--force`. Записи с токенами `sourcecraft-mcp` (сервис `dev.filipov.sourcecraft-mcp`) не читаются и не перезаписываются. Запись секрета репозитория асинхронна: команда ждёт её завершения до минуты. Печатается только итог, например:

```text
Copied sc://acme/web/DEPLOY_KEY to sc://acme/api/DEPLOY_KEY: created (operation 0a1b…: success)
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--profile <имя>` | `$SOURCECRAFT_MCP_PROFILE`, иначе `default` | Профиль токена (один для обоих репозиториев). |
| `--base-url <URL>` | `$SOURCECRAFT_BASE_URL` или `https://api.sourcecraft.tech` | Адрес SourceCraft API. |
| `--force` | выкл. | Перезаписать существующее назначение. |

## call

Вызывает инструмент сервера из консоли.

```text
sourcecraft-mcp call [--profile <имя>] [--allow-write] [--allow-destructive]
    [--allow-path <каталог>]... [--toolsets <набор,...>] [--tools-file <путь>]...
    [--base-url <URL>] [--timeout <секунды>] [--max-response-bytes <байты>]
    [<инструмент> [<имя>=<значение> | <имя>:=<JSON>]... [--args <JSON>|-] [--schema] [--yes] [--raw]]
```

- Без инструмента печатает инструменты, доступные профилю, с уровнем доступа и первой строкой описания. `--schema` печатает схему аргументов инструмента.
- Сервер собирается как в `serve` без флагов: токен и права профиля (на macOS — одобренные), флаги только сужают. По умолчанию включены все наборы (`--toolsets` сужает), наборов по запросу нет. Значения секретов показываются, только если это разрешено в профиле. Клиент MCP работает в этом же процессе, поэтому проверка аргументов, уровни доступа, фильтр `jq` и вырезание секретов те же, что у агента.
- Профиль — `--profile`, иначе `SOURCECRAFT_MCP_PROFILE`, иначе `default`.
- Аргументы: `имя=значение` — тип берётся из схемы инструмента (числа, логические значения, JSON-массивы и объекты; для массива строк — список через запятую), `имя:=JSON` — всегда JSON, `--args` — все аргументы одним JSON-объектом (`-` — из stdin). Флаги команды пишутся до имени инструмента.
- Инструменты уровня удаления спрашивают подтверждение в терминале; `--yes` — без вопроса, без терминала вызов отклоняется.
- Результат: текстовые блоки (JSON — с отступами); `--raw` — ответ MCP целиком. Код выхода — 0, если инструмент выполнился, и 1, если он вернул ошибку (`isError`) или вызов не удался.

```bash
sourcecraft-mcp call get_my_profile
sourcecraft-mcp call list_repository_issues org_slug=acme repo_slug=web page_size=5
sourcecraft-mcp call api_request method=GET path=/user jq=.username
```

## ui

Интерактивный просмотр профилей в терминале.

```text
sourcecraft-mcp ui
```

Вкладки:

- **Profile** — настройки профиля и состояние токена: есть ли токен в хранилище (сам токен не показывается), наборы, динамические наборы, значения секретов, клиент из `connect`.
- **Access** — права профиля и их одобрение. `r`, `w`, `d` — уровень, `a` — добавить каталог, `x` — убрать, `u` — отменить, `s` — сохранить. На macOS сохранение прав шире одобренных спрашивает Touch ID или пароль пользователя macOS.
- **Clients** — регистрации сервера в Claude Code (`~/.claude.json`, `.mcp.json` текущего каталога) и Codex (`$CODEX_HOME/config.toml`): профиль, флаги и расхождения с правами профиля. `f` регистрирует запись `sourcecraft` заново без флагов доступа (остальные аргументы сохраняются). Значения переменных окружения записей не читаются.
- **Account** — проверка токена (`c`): от чьего имени он работает (`GET /user`) и роли пользователя в организациях, которые видны по его пул-реквестам и задачам (до пяти организаций). Показываются только роли, выданные пользователю напрямую: роли через команды не видны. Роли самого токена SourceCraft не сообщает: их видно в Home → Access → Personal access tokens (токен `mcp-<профиль>`).
- **Tools** — инструменты, которые профиль даёт агенту (`c` — загрузить), `Enter` — вызвать с аргументами `имя=значение`, `?` — схема.

`q` или `Esc` — выход, `Tab` и `1`–`5` — вкладки, `F5` — перечитать. Без терминала (агент, CI) команда завершается ошибкой.

## toolsets

```text
sourcecraft-mcp toolsets
```

Печатает наборы инструментов: slug для `--toolsets`, число операций и тег спецификации SourceCraft. Подробнее — [MCP-инструменты](tools.md#наборы-инструментов).

## tools check

```text
sourcecraft-mcp tools check [--tools-file <путь>]...
```

Проверяет файлы [пользовательских инструментов](tools.md#пользовательские-инструменты) так же, как `serve` при запуске, и печатает таблицу: имя, уровень доступа, запрос и файл. Файл `~/.config/sourcecraft-mcp/tools.toml` проверяется всегда, если он есть; `--tools-file` (можно повторять) добавляет файлы, как у `serve`. При ошибке завершается с ненулевым кодом и сообщением с именем файла и инструмента. Токен и сеть не используются.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `SOURCECRAFT_BASE_URL` | Адрес SourceCraft API для `serve`, `connect`, `auth login` и `secret`, если не задан `--base-url`. |
| `SOURCECRAFT_MCP_PROFILE` | Профиль по умолчанию для команд `secret` и `call`. |
| `SOURCECRAFT_MCP_LOG` | Уровень логов в stderr в формате `tracing` `EnvFilter`: `warn` (по умолчанию), `info`, `debug`. Заголовки HTTP-запросов, в том числе токен, в логи не пишутся. |
| `SOURCECRAFT_MCP_CONFIG_DIR` | Каталог с `profiles.toml` и `tools.toml` вместо `~/.config/sourcecraft-mcp`. |
| `CODEX_HOME` | Каталог конфигурации Codex для `connect codex`, по умолчанию `~/.codex`. |

Токен SourceCraft из переменных окружения не читается никогда.
