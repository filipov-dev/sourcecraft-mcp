# Подключение к MCP-клиентам

Сервер работает через stdio: MCP-клиент сам запускает `sourcecraft-mcp serve --profile <профиль>` и общается с ним через stdin и stdout. Токен сервер берёт из системного хранилища по имени профиля, поэтому в конфигурации клиента его нет.

Рекомендуемая схема: **один клиент — один профиль — один токен**. Тогда токен любого агента можно отозвать или заменить, не трогая остальных, а права (уровень доступа, наборы инструментов) настраиваются для каждого клиента отдельно.

## Токен SourceCraft

Сервер работает от имени владельца персонального токена (PAT). Создайте отдельный токен для каждого клиента в форме <https://sourcecraft.dev/me/create-token> — `connect` и `auth login` открывают её в браузере сами. Форма не заполняется заранее, поэтому поменяйте значения по умолчанию:

1. **Имя** — `mcp-<профиль>`, чтобы токен было легко найти и отозвать.
2. **Срок действия** — по умолчанию 1 день; выберите срок дольше (максимум 1 год).
3. **Роли** — для сервера только на чтение достаточно ролей на чтение; если профилю разрешены запись или удаление, нужны роли, которые позволяют менять данные. В Linux и Windows роли токена — единственная настоящая граница доступа (см. [Безопасность](security.md#уровни-доступа)).
4. **Репозитории** — по умолчанию доступ ко всем; при желании ограничьте нужными агенту.

Нажмите «Generate token» и скопируйте значение: SourceCraft показывает его один раз. Документация SourceCraft о ролях: [персональные токены](https://sourcecraft.dev/portal/docs/en/sourcecraft/security/pat).

Браузер не открывается с флагом `--no-browser`, в сессии по SSH (заданы `SSH_CONNECTION` или `SSH_TTY`), в Linux без графической сессии (не заданы `DISPLAY` и `WAYLAND_DISPLAY`) и если запустить его не удалось. Ссылка на форму печатается всегда — её можно открыть на своём компьютере.

Токен вводится только скрытым вводом в `connect` или `auth login`. Его нельзя передать аргументом или переменной окружения, и ни одна команда его не печатает.

## Claude Code и Codex: `connect`

```bash
sourcecraft-mcp connect claude-code
sourcecraft-mcp connect codex
```

Что делает `connect`:

1. Проверяет клиент: для Claude Code — что команда `claude` есть в `PATH`; для Codex — что выбрана область `user`.
2. Если для профиля ещё нет токена, открывает в браузере форму создания токена, показывает, как её заполнить, и просит вставить токен (ввод скрыт). Если токен уже сохранён, использует его.
3. Проверяет токен запросом `GET /user` и показывает, от имени какого пользователя будет работать сервер (`--skip-check` пропускает проверку).
4. Сохраняет токен в системное хранилище (сервис `dev.filipov.sourcecraft-mcp`, учётная запись — имя профиля), а настройки профиля — в `~/.config/sourcecraft-mcp/profiles.toml` (в Windows — `%APPDATA%\sourcecraft-mcp\profiles.toml`). С `--allow-write` или `--allow-destructive` меняет права профиля; на macOS повышение прав спрашивает Touch ID или пароль пользователя macOS.
5. Показывает, что изменится в конфигурации клиента, и после подтверждения регистрирует сервер с именем `sourcecraft`:
   - **Claude Code** — через `claude mcp add --scope <область> sourcecraft -- <путь>/sourcecraft-mcp serve --profile <профиль> …`. Если сервер `sourcecraft` уже есть в этой области, `connect` предложит заменить его.
   - **Codex** — записью `[mcp_servers.sourcecraft]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`). Остальные записи, комментарии и форматирование файла сохраняются; существующая запись `sourcecraft` заменяется.

После этого перезапустите клиент.

По умолчанию профиль называется как клиент (`claude-code`, `codex`); другое имя — `--profile`. Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

### Права и наборы инструментов

Флаги доступа `connect` меняют права профиля, а в команду запуска сервера не попадают: клиент запускает `serve --profile <профиль>`, и права берутся из профиля. Остальные флаги сохраняются в профиль и попадают в команду запуска:

| Флаг | Что делает |
| --- | --- |
| `--allow-write` | Права профиля: инструменты, которые создают и меняют данные. |
| `--allow-destructive` | Права профиля: инструменты удаления и другие необратимые операции; включает запись. |
| `--toolsets a,b` | Только указанные наборы инструментов (`sourcecraft-mcp toolsets`). |
| `--dynamic-toolsets` | Наборы включаются агентом по запросу (см. [ниже](#динамические-наборы-инструментов)). |
| `--allow-secret-values` | Разрешить агенту запрашивать значения секретов (см. [Безопасность](security.md#раскрытие-значений)). |
| `--scope user\|project` | Область регистрации. `project` — только Claude Code: файл `.mcp.json` в текущем каталоге. Codex поддерживает только `user`. |
| `-y`, `--yes` | Не спрашивать подтверждение перед изменением конфигурации клиента. |
| `--skip-check` | Не проверять токен запросом к API. |
| `--no-browser` | Не открывать форму создания токена в браузере, только напечатать ссылку. |

Пример: Codex с правом записи только в задачи и пул-реквесты.

```bash
sourcecraft-mcp connect codex --allow-write \
  --toolsets repository,repository-pullrequest,repository-pullrequest-comments,issues,issues-comments
```

Права профиля удобнее менять в `sourcecraft-mcp ui` (вкладка Access: `r`, `w`, `d`, каталоги — `a` и `x`, сохранение — `s`); перезапуск клиента после этого нужен, а `connect` — нет. Можно и запустить `connect` ещё раз: токен не запрашивается заново, а запись в клиенте перезаписывается. Без флагов доступа права профиля не меняются; остальные флаги, которые вы не указали, сбрасываются к значениям по умолчанию (все наборы, без динамических наборов и значений секретов). На macOS при отказе в Touch ID или пароле профиль сохраняет прежние права, а токен и регистрация всё равно сохраняются.

Регистрации, сделанные старыми версиями с флагами доступа в `args`, продолжают работать, пока флаги не шире прав профиля. Повторный `connect` или клавиша `f` на вкладке Clients в `sourcecraft-mcp ui` переписывают их без флагов.

С `--scope project` команда запуска попадает в `.mcp.json` проекта, но токен остаётся в хранилище того, кто запускал `connect`, а в команде записан абсолютный путь к бинарнику на его машине. Другим участникам проекта нужен свой токен под тем же именем профиля (`sourcecraft-mcp auth login --profile <профиль>`) и бинарник по тому же пути.

### Динамические наборы инструментов

С `--dynamic-toolsets` сервер начинает с пяти инструментов (`api_search`, `api_request`, `list_toolsets`, `enable_toolset`, `disable_toolset`), а агент включает нужные наборы сам ([подробнее](tools.md#динамические-наборы)). Это работает только в клиентах, которые перечитывают список инструментов по уведомлению `notifications/tools/list_changed`. Состояние на ноябрь 2026:

| Клиент | `list_changed` | Рекомендация |
| --- | --- | --- |
| Claude Code | Поддерживается: в интерактивном режиме список перечитывается без переподключения; в режиме `-p` и Agent SDK обновляется только список инструментов. | Флаг не нужен: Claude Code и так загружает описания инструментов MCP по требованию (tool search). Можно включить, если tool search выключен (`ENABLE_TOOL_SEARCH=false`). |
| Codex | Не поддерживается: Codex не перечитывает список инструментов по уведомлению (открытые задачи в репозитории `openai/codex`). | Не включайте `--dynamic-toolsets`: включённые инструменты не появятся, агенту останутся только `api_search` и `api_request`. Чтобы сократить список, используйте `--toolsets`. |

Если клиент не перечитал список, агент всё равно может вызвать любую операцию в пределах уровня доступа через `api_request`: об этом сказано в ответе `enable_toolset` и в инструкциях сервера.

## Другие клиенты: ручное подключение

`connect` настраивает только Claude Code и Codex. Любой клиент, который умеет запускать stdio MCP-серверы, подключается вручную.

1. Сохраните токен в отдельный профиль:

   ```bash
   sourcecraft-mcp auth login --profile cursor
   ```

   Команда покажет инструкцию по созданию токена, примет его скрытым вводом, проверит и сохранит в системное хранилище. В `profiles.toml` появится профиль с настройками по умолчанию (только чтение).

2. Узнайте абсолютный путь к бинарнику:

   ```bash
   command -v sourcecraft-mcp
   ```

   Клиенты, запущенные не из терминала (из Dock, меню приложений), часто не видят `PATH` вашей оболочки, поэтому в конфигурации надёжнее указать полный путь.

3. Зарегистрируйте в клиенте stdio-сервер: команда — путь к `sourcecraft-mcp`, аргументы — `serve --profile <профиль>`. Права задаются в профиле (`sourcecraft-mcp ui`), а не флагами в записи клиента: флаги `serve` их только сужают. Формат `mcpServers`, который понимает большинство клиентов:

   ```json
   {
     "mcpServers": {
       "sourcecraft": {
         "command": "/opt/homebrew/bin/sourcecraft-mcp",
         "args": ["serve", "--profile", "cursor"]
       }
     }
   }
   ```

   Где лежит этот файл, зависит от клиента; смотрите его документацию о подключении MCP-серверов (stdio, «command»). Переменные окружения и токен в записи не нужны.

4. Перезапустите клиент и проверьте, что у сервера `sourcecraft` появились инструменты.

Флаги в `args` (`--toolsets`, `--dynamic-toolsets`, `--allow-secret-values` и др.) описаны в [справочнике CLI](cli.md#serve). Права (уровень доступа и каталоги `allow_path`) сервер берёт из профиля в `profiles.toml`, а без настроек работает только на чтение; `--allow-write`, `--allow-destructive` и `--allow-path` в `args` могут их только сузить. Без `--toolsets` действуют наборы профиля, без них — все.

### Ручная регистрация в Claude Code и Codex

Если вы не хотите, чтобы `connect` менял конфигурацию, зарегистрируйте сервер сами после `auth login`:

```bash
claude mcp add --scope user sourcecraft -- "$(command -v sourcecraft-mcp)" serve --profile claude-code
```

```toml
# ~/.codex/config.toml
[mcp_servers.sourcecraft]
command = "/opt/homebrew/bin/sourcecraft-mcp"
args = ["serve", "--profile", "codex"]
```

## Windows

`connect`, `auth` и `serve` работают в Windows так же, команды можно запускать из PowerShell, `cmd` или Git Bash.

- **Токен** хранится в Windows Credential Manager: общие учётные данные `<профиль>.dev.filipov.sourcecraft-mcp` (Панель управления → Диспетчер учётных данных → Учётные данные Windows). Настройки профилей — в `%APPDATA%\sourcecraft-mcp\profiles.toml`. Credential Manager доступен только в сеансе, вошедшем с паролем: в SSH-сеансе со входом по ключу, в службе или задаче планировщика без сохранённого пароля Windows не даёт хранилища (ошибка «A specified logon session does not exist»). Запускайте `connect`, `auth` и MCP-клиент в обычном сеансе пользователя; для агента на другой машине есть [HTTP-режим](http.md).
- **Claude Code**: `connect claude-code` вызывает `claude mcp add`, поэтому команда `claude` должна быть в `PATH` (подходят и `claude.exe` из установщика Claude Code, и `claude.cmd` из npm).
- **Codex**: `connect codex` пишет в `%USERPROFILE%\.codex\config.toml` (или в `config.toml` каталога из `CODEX_HOME`).
- В конфигурацию клиента записывается полный путь к `sourcecraft-mcp.exe`, из которого запущен `connect`, например `C:\Users\<имя>\AppData\Local\Programs\sourcecraft-mcp\sourcecraft-mcp.exe`. Обновляйте бинарник заменой файла по тому же пути (см. [Установка](install.md#windows)), тогда `connect` повторять не нужно.

Ручная регистрация в Codex в Windows (в TOML обратные косые черты внутри одинарных кавычек не экранируются):

```toml
# %USERPROFILE%\.codex\config.toml
[mcp_servers.sourcecraft]
command = 'C:\Users\<имя>\AppData\Local\Programs\sourcecraft-mcp\sourcecraft-mcp.exe'
args = ["serve", "--profile", "codex"]
```

## Рабочий каталог и локальные файлы

Инструменты, которые загружают или сохраняют файлы, работают только с путями внутри рабочего каталога сервера, системного временного каталога и каталогов `allow_path` профиля. Рабочий каталог сервера — тот, в котором клиент его запустил (обычно каталог проекта). Если клиент запускает сервер в домашнем каталоге или в корне файловой системы, рабочий каталог в разрешённые не попадает: добавьте нужные каталоги в права профиля: `sourcecraft-mcp ui`, вкладка Access, клавиша `a`. Подробнее — [Безопасность](security.md#локальные-файлы).

## Несколько профилей

Профилей может быть сколько угодно: например, `claude-code` только на чтение и `codex-deploy` с правом записи в другой организации. Проверить профиль:

```bash
sourcecraft-mcp auth status --profile codex
```

Команда показывает, сохранён ли токен (не его значение), клиент, права профиля, одобрение на macOS и выбранные наборы. `sourcecraft-mcp ui` показывает все профили сразу, их регистрации в клиентах и — по запросу — от чьего имени работает токен и роли пользователя в организациях.

## Отключение

1. Удалите запись `sourcecraft` из клиента: `claude mcp remove --scope user sourcecraft`, запись `[mcp_servers.sourcecraft]` из `~/.codex/config.toml` или запись из конфигурации другого клиента.
2. Удалите токен из хранилища и настройки профиля:

   ```bash
   sourcecraft-mcp auth logout --profile codex --forget
   ```

3. Отзовите токен в SourceCraft: Home → Access → Personal access tokens.
