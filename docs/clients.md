# Подключение к MCP-клиентам

Сервер работает через stdio: MCP-клиент сам запускает `sourcecraft-mcp serve --profile <профиль>` и общается с ним через stdin и stdout. Токен сервер берёт из системного хранилища по имени профиля, поэтому в конфигурации клиента его нет.

Рекомендуемая схема: **один клиент — один профиль — один токен**. Тогда токен любого агента можно отозвать или заменить, не трогая остальных, а права (уровень доступа, наборы инструментов) настраиваются для каждого клиента отдельно.

## Токен SourceCraft

Сервер работает от имени владельца персонального токена (PAT). Создайте отдельный токен для каждого клиента:

1. Откройте <https://sourcecraft.dev> и войдите.
2. В левой панели откройте Home → Access → Personal access tokens и нажмите «Generate new token».
3. Назовите токен, например, `mcp-<профиль>`, выберите срок действия, доступ к репозиториям и роли. Для сервера только на чтение достаточно ролей на чтение.
4. Нажмите «Generate token» и скопируйте значение: SourceCraft показывает его один раз.

Документация SourceCraft: [персональные токены](https://sourcecraft.dev/portal/docs/en/sourcecraft/security/pat).

Токен вводится только скрытым вводом в `connect` или `auth login`. Его нельзя передать аргументом или переменной окружения, и ни одна команда его не печатает.

## Claude Code и Codex: `connect`

```bash
sourcecraft-mcp connect claude-code
sourcecraft-mcp connect codex
```

Что делает `connect`:

1. Проверяет клиент: для Claude Code — что команда `claude` есть в `PATH`; для Codex — что выбрана область `user`.
2. Если для профиля ещё нет токена, показывает инструкцию по созданию токена и просит вставить его (ввод скрыт). Если токен уже сохранён, использует его.
3. Проверяет токен запросом `GET /user` и показывает, от имени какого пользователя будет работать сервер (`--skip-check` пропускает проверку).
4. Сохраняет токен в системное хранилище (сервис `dev.filipov.sourcecraft-mcp`, учётная запись — имя профиля), а настройки профиля — в `~/.config/sourcecraft-mcp/profiles.toml`.
5. Показывает, что изменится в конфигурации клиента, и после подтверждения регистрирует сервер с именем `sourcecraft`:
   - **Claude Code** — через `claude mcp add --scope <область> sourcecraft -- <путь>/sourcecraft-mcp serve --profile <профиль> …`. Если сервер `sourcecraft` уже есть в этой области, `connect` предложит заменить его.
   - **Codex** — записью `[mcp_servers.sourcecraft]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`). Остальные записи, комментарии и форматирование файла сохраняются; существующая запись `sourcecraft` заменяется.

После этого перезапустите клиент.

По умолчанию профиль называется как клиент (`claude-code`, `codex`); другое имя — `--profile`. Имя профиля: 1–64 символа из `A-Z`, `a-z`, `0-9`, `.`, `_`, `-`, не начинается с `-`.

### Права и наборы инструментов

Флаги `connect` сохраняются в профиль и попадают в команду запуска сервера в конфигурации клиента:

| Флаг | Что делает |
| --- | --- |
| `--allow-write` | Инструменты, которые создают и меняют данные. |
| `--allow-destructive` | Инструменты удаления и другие необратимые операции. |
| `--toolsets a,b` | Только указанные наборы инструментов (`sourcecraft-mcp toolsets`). |
| `--allow-secret-values` | Разрешить агенту запрашивать значения секретов (см. [Безопасность](security.md#раскрытие-значений)). |
| `--scope user\|project` | Область регистрации. `project` — только Claude Code: файл `.mcp.json` в текущем каталоге. Codex поддерживает только `user`. |
| `-y`, `--yes` | Не спрашивать подтверждение перед изменением конфигурации клиента. |
| `--skip-check` | Не проверять токен запросом к API. |

Пример: Codex с правом записи только в задачи и пул-реквесты.

```bash
sourcecraft-mcp connect codex --allow-write \
  --toolsets repository,repository-pullrequest,repository-pullrequest-comments,issues,issues-comments
```

Чтобы поменять права, запустите `connect` ещё раз с нужными флагами: токен не запрашивается заново, а профиль и запись в клиенте перезаписываются целиком. Флаги, которые вы не указали, сбрасываются к значениям по умолчанию (только чтение, все наборы).

С `--scope project` команда запуска попадает в `.mcp.json` проекта, но токен остаётся в хранилище того, кто запускал `connect`, а в команде записан абсолютный путь к бинарнику на его машине. Другим участникам проекта нужен свой токен под тем же именем профиля (`sourcecraft-mcp auth login --profile <профиль>`) и бинарник по тому же пути.

## Другие клиенты: ручное подключение

`connect` настраивает только Claude Code и Codex. Любой клиент, который умеет запускать stdio MCP-серверы, подключается вручную.

1. Сохраните токен в отдельный профиль:

   ```bash
   sourcecraft-mcp auth login --profile cursor
   ```

   Команда покажет инструкцию по созданию токена, примет его скрытым вводом, проверит и сохранит в системное хранилище. В `profiles.toml` появится профиль с настройками по умолчанию (только чтение).

2. Узнайте абсолютный путь к бинарнику:

   ```bash
   command -v sourcecraft-mcp
   ```

   Клиенты, запущенные не из терминала (из Dock, меню приложений), часто не видят `PATH` вашей оболочки, поэтому в конфигурации надёжнее указать полный путь.

3. Зарегистрируйте в клиенте stdio-сервер: команда — путь к `sourcecraft-mcp`, аргументы — `serve --profile <профиль>` и нужные флаги. Формат `mcpServers`, который понимает большинство клиентов:

   ```json
   {
     "mcpServers": {
       "sourcecraft": {
         "command": "/opt/homebrew/bin/sourcecraft-mcp",
         "args": ["serve", "--profile", "cursor", "--allow-write"]
       }
     }
   }
   ```

   Где лежит этот файл, зависит от клиента; смотрите его документацию о подключении MCP-серверов (stdio, «command»). Переменные окружения и токен в записи не нужны.

4. Перезапустите клиент и проверьте, что у сервера `sourcecraft` появились инструменты.

Флаги в `args` (`--allow-write`, `--allow-destructive`, `--toolsets`, `--allow-secret-values`, `--allow-path` и др.) описаны в [справочнике CLI](cli.md#serve). Если флаги доступа и `--toolsets` в `args` не указаны, сервер берёт их из настроек профиля в `profiles.toml`, а без настроек работает только на чтение со всеми наборами.

### Ручная регистрация в Claude Code и Codex

Если вы не хотите, чтобы `connect` менял конфигурацию, зарегистрируйте сервер сами после `auth login`:

```bash
claude mcp add --scope user sourcecraft -- "$(command -v sourcecraft-mcp)" serve --profile claude-code
```

```toml
# ~/.codex/config.toml
[mcp_servers.sourcecraft]
command = "/opt/homebrew/bin/sourcecraft-mcp"
args = ["serve", "--profile", "codex"]
```

## Рабочий каталог и локальные файлы

Инструменты, которые загружают или сохраняют файлы, работают только с путями внутри рабочего каталога сервера, системного временного каталога и каталогов из `--allow-path`. Рабочий каталог сервера — тот, в котором клиент его запустил (обычно каталог проекта). Если клиент запускает сервер в домашнем каталоге или в корне файловой системы, рабочий каталог в разрешённые не попадает: добавьте нужные каталоги через `--allow-path`. Подробнее — [Безопасность](security.md#локальные-файлы).

## Несколько профилей

Профилей может быть сколько угодно: например, `claude-code` только на чтение и `codex-deploy` с правом записи в другой организации. Проверить профиль:

```bash
sourcecraft-mcp auth status --profile codex
```

Команда показывает, сохранён ли токен (не его значение), клиент, разрешены ли запись и удаление и выбранные наборы.

## Отключение

1. Удалите запись `sourcecraft` из клиента: `claude mcp remove --scope user sourcecraft`, запись `[mcp_servers.sourcecraft]` из `~/.codex/config.toml` или запись из конфигурации другого клиента.
2. Удалите токен из хранилища и настройки профиля:

   ```bash
   sourcecraft-mcp auth logout --profile codex --forget
   ```

3. Отзовите токен в SourceCraft: Home → Access → Personal access tokens.
